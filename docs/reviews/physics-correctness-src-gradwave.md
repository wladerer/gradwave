### 1. [high] Trust-region trial mutates autograd leaves in-place while the double-backward (Hvp) graph over those leaves is live and reused, corrupting/crashing Newton-CG on any rejected step
`opt/newton.py:213` · kind: autodiff

**Evidence.** In `_newton_inner`, `grads` is built once per Newton step with create_graph=True (line 186) and captured by `hvp` via default-arg `_g=grads` (line 200-202). The 8-iteration trial loop (line 206) reuses that SAME retained graph across trials. On a rejected trial the leaves are mutated in place: `t.add_(pi)` (line 214-215) then `t.sub_(pi)` (line 233-235) under torch.no_grad. In-place ops bump the leaves' version counters even under no_grad and even though the value is restored. The next trial then calls `steihaug_cg(grads, hvp, ...)` -> `hvp(d)` -> `torch.autograd.grad(dot(grads,v), leaves, retain_graph=True)`, which re-traverses the retained double-backward graph. That graph directly saves the leaf `frac_p`: inside `joint_energy`, `pos_e = frac @ a_e` (joint.py:242) is a matmul whose backward saves BOTH operands because, in the default variable-cell case (fix_cell=False), both `frac_p` and `a_e` (via `eps_p`) require grad; the grad-of-a_e branch `frac.T @ grad_pos` references the actual `frac_p` tensor. Its bumped version triggers PyTorch's 'one of the variables needed for gradient computation has been modified by an inplace operation' RuntimeError. The graph is only rebuilt after an ACCEPTED step (`del grads; e_val, grads = energy_and_grad(leaves)`, line 240-241), so the code works only when every trust-region step is accepted on the first trial; any rejected step (the normal case that shrinks delta) crashes. The `try/except RuntimeError` at line 217-222 wraps only the no_grad `energy(leaves)` forward, not the next trial's `steihaug_cg`/`hvp`, so the error propagates out of `newton_cg_relax` instead of degrading to the converged=False nested fallback.

**Direction.** Do not reuse the create_graph gradient graph across in-place leaf updates. Either (a) recompute grads (energy_and_grad) at the top of each trial before any Hvp, or (b) perform trial displacements on detached copies / restore via out-of-place assignment on a separate parameter buffer so the retained graph's saved leaf tensors are never version-bumped, or (c) build the Hvp against a functional (torch.func.jvp/vjp) closure over cloned leaves. Add a regression test that forces at least one trust-region rejection (e.g. a poor initial trust_radius) in the default fix_cell=False path.

### 2. [high] _bare_response_occ double-applies the spin factor for nspin=1, making χ0 twice too large
`postscf/hubbard_u.py:138` · kind: factor-of-2 / occupation-spin-factor error

**Evidence.** occupations_and_entropy returns degeneracy*f = g·f (occupations.py:165-166; for nspin=1, g_spin=2 so w = 2f). This w is passed directly into occupation_matrices at line 139, but occupation_matrices expects a PER-SPIN weight f∈[0,1]: it weights becp·becp* linearly by `occ` (hubbard.py:170-181) and the Dudarev energy Tr[n(1−n)] it feeds requires eigenvalues in [0,1]. Every other caller confirms this — hubbard_occ_and_energy passes `0.5*occ_s[0]` (=f) for nspin=1 (hubbard.py:214), as do scf/loop.py:1156 and uspp_loop.py:666, and the sibling _site_occupations here uses `w = 0.5*occ_sp` (=f) at hubbard_u.py:87. So Tr(mats) here is already 2·Tr[n(f)]; line 142 then multiplies by another 2.0, yielding N_I = 4·Tr[n(f)] versus the physically correct 2·Tr[n(f)] = Σ_σ Tr[n^{Iσ}] that _site_occupations produces. The in-code comment at lines 136-137 ('occupation_matrices expects g·f') is the wrong half of the contract. Impact: in linear_response_u (nspin=1, gaussian smearing default) χ0 = dN_bare/dα is computed from _bare_response_occ (2× scale) while the interacting χ = dN/dα comes from _site_occupations (correct scale), so U = (χ0^{-1} − χ^{-1}) mixes two incompatible occupation scales and returns a wrong Hubbard U. nspin=2 (g=1) is unaffected.

**Direction.** For nspin=1 pass per-spin f into occupation_matrices (e.g. drop the degeneracy in occupations_and_entropy or multiply w by 0.5) and keep the trailing ×2.0; or equivalently feed g·f and drop the ×2.0 — but match whichever convention _site_occupations uses so χ and χ0 are on the same scale. Correct comment at lines 136-137.

### 3. [medium] Capacitor stress functional (esm_energy_strained) does not match the energy/force functional (esm_energy) for a net-charged cell
`core/energies/esm.py:445` · kind: energy/stress inconsistency (broken derivative identity)

**Evidence.** For mode='capacitor' the value/force path esm_energy (line 404) computes the energy via _capacitor_grounded_de, which splits rho_tot = rho_n + rho_q, gives the net charge q=(rho_tot.sum()*dvol) a smooth carrier rho_q, and treats the net-charge terms with the spectral reference s_q = v_cap(rho_q) - v_periodic(rho_q) (lines 371-376). The stress path esm_energy_strained (lines 445-448) instead uses the PLAIN matched functional dv_grounded = esm_delta_potential + hartree_potential_capacitor - hartree_potential_esm, i.e. 0.5*(rho_tot*_matched_cap_dv(rho_tot)). _capacitor_grounded_de reduces to exactly this plain matched form only when q->0 (rho_q->0), as its own docstring states (line 368). Therefore for a net-charged capacitor cell (the constant-potential / biased-electrochemistry case that _capacitor_grounded_de was written to support) the stress returned by differentiating esm_energy_strained is NOT dE/dstrain of the energy actually reported by esm_energy: stress no longer corresponds to the reported total energy, violating the force/stress = -dE/d(deformation) identity. Neutral cells and vacuum mode are unaffected (functionals coincide there). esm_energy_strained's docstring claims 'the capacitor sub-terms flow through the same differentiable cell', implying it is meant to mirror esm_energy's capacitor energy.

**Direction.** Refactor _capacitor_grounded_de to accept explicit strained (cell, g_cart/g2, volume, shape) inputs (as _gaussian_ion / esm_delta_potential already do) and call that same function from both esm_energy and esm_energy_strained, so the charged-cell grounded correction is the single source of the capacitor energy and its strain derivative is the stress. Alternatively, if charged-capacitor stress is intentionally unsupported, raise on q != 0 in esm_energy_strained rather than silently returning the stress of a different functional.

### 4. [medium] ε∞ dielectric columns built in float32 via bare torch.tensor / torch.eye (default-dtype leak)
`postscf/dielectric.py:272` · kind: dtype-precision

**Evidence.** The package never calls torch.set_default_dtype (verified: grep of src/ finds none; torch.get_default_dtype()==float32 in this env). In `_dielectric_born` the non-symmetrized path builds `col = torch.tensor([float(...) for a in range(3)])` (line 272) and `eps_mat[:, b_dir] = 1.0 * torch.eye(3)[:, b_dir] - (16.0*math.pi*E2/vol)*col` (line 288) — both `torch.tensor([...])` and `torch.eye(3)` default to float32, so the reported ε∞ tensor carries only ~7 significant digits despite eps_mat being allocated RDTYPE (the assignment upcasts already-rounded float32 values). The same pattern repeats in `_dielectric_born_spin` (col line 519, eye line 539) and `_dielectric_born_soc` (col line 775, eye line 791). The IBZ-symmetrized branch is written correctly with `torch.eye(3, dtype=RDTYPE)` (line 303) and a float64 col_mat (torch.zeros(3,3,dtype=RDTYPE), line 373), confirming this is an inconsistent omission rather than intent. Two consequences: (1) ε∞ / Born prefactor precision is capped at float32, undermining the docstring's 'exact, solver-precision self-oracle' claim (test_dielectric_soc.py) which would then only agree to ~1e-6; (2) the outer fixed-point convergence gate `float((col - col_prev).abs().max()) < outer_tol` with default outer_tol=1e-7 (signature line 152) operates right at float32 epsilon (~1.19e-7), so on col values of O(1) the loop can stall (never drop below the float32 noise floor -> spurious 'E-field response not converged' RuntimeError) or false-converge one iteration early. Violates the package precision contract (dtypes.py: 'All physics runs in float64/complex128; single precision is not supported').

**Direction.** Build col with an explicit dtype (e.g. torch.tensor([...], dtype=RDTYPE) or torch.stack of the float64 scalar tensors) and use torch.eye(3, dtype=RDTYPE) in all three non-symmetrized branches, matching the symmetrized path at line 303.

### 5. [medium] default_nbands ignores spin polarization; majority-spin channel can exceed the band count
`scf/setup_common.py:137` · kind: numerical-correctness / band-count · refutes: 1

**Evidence.** default_nbands(n_electrons) computes nocc = ceil(n_electrons/2.0) (the PARAMAGNETIC occupied count) and returns max(ceil(nocc*1.2), nocc+4). For nspin=2 collinear (and the spinor path), the same nbands is used per spin channel, but the majority channel holds (N+M)/2 states, where M is the total moment. Once M is a sizable fraction of N the default under-provisions: e.g. a ~20-atom Fe supercell (N~160 valence, moment ~44 muB) gives nocc=80 -> nbands=max(ceil(80*1.2)=96, 84)=96, while N_up~102 > 96. The Fermi solver then cannot place all majority-spin electrons (no band to occupy), so the converged electron count and free energy are wrong, and no smearing can compensate. The '+4'/'20%' headroom is measured against the wrong (spin-averaged) occupancy; the function has no M dependence at all. Only bites larger magnetic cells (for small cells nocc+4 dominates and hides it), which is why it can pass small-system tests.

**Direction.** Make the default depend on the seeded/total moment for nspin>1: size nbands off the larger spin channel, i.e. nocc_max = ceil((N + |M|)/2), and return max(ceil(nocc_max*1.2), nocc_max + 4). Alternatively verify every caller (setup_system / setup_uspp / noncollinear) explicitly overrides nbands for magnetic runs; if so, downgrade to a docstring caveat.

### 6. [low] DOS applies spin degeneracy 2 to noncollinear (spinor) results, double-counting states
`analysis.py:141` · kind: spin-factor

**Evidence.** dos_frame keys the spin degeneracy purely off parameters['nspin']: `g_spin = 2.0 if nspin == 1 else 1.0` (line 141). A noncollinear/spinor SCF (NCResult) has no nspin field, so build_summary defaults it to 1 (api.py:474 `nspin = int(_get(res, 'nspin', 1) or 1)`), yet its bands are spinor states holding ONE electron each. dos_frame ignores occupations and reads only eigenvalues + kweights, so on a noncollinear summary it multiplies every state by g_spin=2, making the DOS integrate to 2*nbands instead of nbands (factor-of-2 too large). Collinear nspin=1 (spatial orbitals, 2 electrons/band) is correct; only the spinor case is wrong.

**Direction.** Distinguish the noncollinear formalism in the DOS degeneracy (e.g. carry a 'noncollinear'/formalism flag in the parameters block and use g_spin=1 for spinor eigenvalues), rather than inferring degeneracy from nspin==1 alone.

### 7. [low] Trailing transpose-symmetrization is applied AFTER the acoustic sum rule, reintroducing an ASR violation so the three Γ acoustic modes are not exactly zero
`postscf/phonons.py:172` · kind: sum-rule/numerical-correctness

**Evidence.** gamma_hessian does: (1) line 167 h2=0.5*(h2+h2.T) symmetrize; (2) lines 169-170 ASR: hblk[a,:,a,:] -= hblk[a].sum(axis=1); (3) line 172 return 0.5*(h2+h2.T) — a SECOND symmetrization applied after the ASR. The ASR self-block correction Σ_b H[a,i,b,j] is not symmetric in (i,j) in general, so the ASR-corrected diagonal block acquires an antisymmetric part; the trailing 0.5*(h2+h2.T) removes exactly that antisymmetric part, which changes the row sum Σ_b H[a,:,b,:] by 0.5*(C - Cᵀ) != 0 (C = the correction). Net: after line 172 the acoustic sum rule no longer holds exactly, so eigvalsh in gamma_frequencies yields three near-zero (not machine-zero) acoustic modes, contrary to the docstring's claim that ASR is enforced. The effect is order the antisymmetric noise in the reconstructed columns, hence small for well-converged input but conceptually undermines the sum rule the code sets out to impose.

**Direction.** Make ASR the last operation: either symmetrize only the self-block correction before subtracting it (subtract 0.5*(C+Cᵀ)), or reorder so the transpose-symmetrization at line 167 is the sole symmetrization and the ASR loop runs last with no subsequent re-symmetrize. Then Σ_b H[a,:,b,:]=0 holds exactly and the Γ acoustic modes come out machine-zero.

### 8. [low] both_faces vacuum split at density argmax mishandles a slab straddling the periodic boundary
`postscf/work_function.py:65` · kind: pbc_wraparound · refutes: 1

**Evidence.** vacuum_level(..., both_faces=True) splits the open axis into segments (0,mid) and (mid,nz) with mid=int(torch.argmax(rho_z)). This assumes the slab sits in the interior with vacuum at both ends. If the slab is centered on the cell edge (vacuum in the middle, slab wrapping z=0/z=nz under PBC), argmax lands near an edge: one segment becomes tiny or empty, so torch.topk(seg_rho, k, largest=False) on an empty/short slice returns a wrong face potential or raises, and the two 'faces' are no longer separated correctly. The non-both_faces path is unaffected (global min-density correctly finds vacuum regardless of position).

**Direction.** Identify the two vacuum faces by the minimum-density plane (roll the profile so the lowest-density point is at an edge, or split at argmin of rho_z) rather than splitting at the density maximum; guard against an empty segment.

### 9. [low] Composite-Simpson index weights are wrong for n=4 (degenerate 1/3 region), ~11% over-integration
`pseudo/radial.py:51` · kind: numerical-quadrature

**Evidence.** _simpson_index_weights guards only `n < 4` (line 44-45), so n=4 is accepted. In the even branch m = n-3 = 1, so the '1/3 rule over the first n-3 points' collapses to a single point that is also the shared boundary of the 3/8 closure: w[0] is set to 1/3 (line 55) then w[m-1]=w[0] is overwritten with 1/3+3/8 (line 56), leaving w=[0.7083,1.125,1.125,0.375]. The correct pure 3/8 rule over 4 points is [3/8,9/8,9/8,3/8]. Verified at runtime: n=4 -> sum(w)=3.3333 vs the exact index-length n-1=3 (an ~11% error); n=5,6,7,8 are all exact. The 1/3 sub-rule needs an odd count >=3, i.e. m=n-3>=3 => n>=6, so only n=4 is degenerate. Any radial integral (simpson/sbt: densities, projector/local form factors, alpha_z) done on an exactly-4-point mesh would be biased; real UPF/projector meshes are hundreds of points so this is latent, not hit in practice, but n=4 is an accepted input per the explicit guard.

**Direction.** Either raise the guard to require n>=5 for the even branch (n=4 has no valid 1/3+3/8 split), or special-case n=4 to the plain 3/8 rule weights [3/8,9/8,9/8,3/8].

### 10. [low] atom_scale documented as 'overrides species_scale' but code applies both multiplicatively
`scf/guess.py:30` · kind: doc/code-contract-mismatch · refutes: 1

**Evidence.** Line 30 declares `atom_scale=None,  # per-ATOM factor (AFM seeds); overrides species_scale`. But species_scale is baked into the radial table at line 46 (`scale = ... float(species_scale[s]); table = scale * ...`) unconditionally, while atom_scale is applied separately to the structure factor at lines 55-58. If a caller ever passes BOTH, the per-species factor is NOT overridden — the two multiply, silently double-scaling the SAD seed for that species (a mis-normalized initial density, later only partially rescued by the n_electrons renorm at line 65/74 since atom_scale shifts the G=0 weight). Currently unreachable: grepping src/ shows no caller passes species_scale, so every atom_scale call has species_scale=None. This is a latent trap for future magnetic/spin-split seeders, not an active bug; impact is bounded because the SAD guess is detached and refined by the SCF.

**Direction.** Either honor the 'overrides' contract (skip the species_scale table factor when atom_scale is not None) or fix the docstring to say the two factors compose multiplicatively.

### 11. [low] Thomas-Fermi q^2 comment mislabels units (bohr^-1 quantity called bohr^-2; docstring writes /a0^2)
`scf/local_tf.py:77` · kind: unit-consistency · refutes: 1

**Evidence.** set_density computes kf = (3*pi^2*n_bohr)^(1/3) [bohr^-1] then q2_bohr = (4/pi)*kf and comments it as 'bohr^-2', then q2_ang = q2_bohr/(_BOHR**2) to Angstrom^-2. Dimensionally (4/pi)*k_F with k_F in bohr^-1 is bohr^-1, not bohr^-2; the module docstring (line 18) writes 'q^2_TF(r) = (4/pi) k_F(r) / a0^2', whereas the physical Thomas-Fermi relation is k_TF^2 = (4/pi) k_F / a0 (single power of a0). The code is NUMERICALLY CORRECT only because it works in Hartree atomic units where a0 = 1 bohr (verified: Al bulk gives ~2.05 Angstrom^-1, the right magnitude, and the constant-density limit q^2->q0_max^2 reproduces bare Kerker). The Angstrom conversion q2_bohr/_BOHR**2 is the correct bohr^-2 -> Angstrom^-2 factor. Risk: the comment/docstring inconsistency invites a maintainer to 'correct' the units by inserting a /_BOHR (or /a0^2) factor, which would corrupt the screening wavevector. No behavioral bug today.

**Direction.** Fix the comment to state q^2_TF = (4/pi) k_F / a0 with a0 = 1 bohr implicit (so numerically (4/pi)*kf is already in bohr^-2), or make the a0=1 assumption explicit; leave the arithmetic unchanged.

### G2. [medium] ESM capacitor stress functional (esm_energy_strained) drops the net-charge reference split that the energy/force functional applies
`core/energies/esm.py:445` · kind: drifted-duplicate

**Evidence.** The energy/force path esm_energy (capacitor) routes through _capacitor_grounded_de (esm.py:362), which splits rho_tot = rho_n (neutral) + rho_q (smooth net charge) and treats the net charge with a distinct spectral reference (`s_q = hartree_potential_capacitor(rho_q) - hartree_potential_r(rho_q,...)`), explicitly 'valid for a charged cell'. The stress path esm_energy_strained (capacitor, esm.py:445) instead computes `dv_grounded = esm_delta_potential + hartree_potential_capacitor(bias=0) - hartree_potential_esm` applied to the FULL rho_tot and `de = 0.5*(rho_tot*dv_grounded).sum()*dvol` — this is exactly _matched_cap_dv(rho_tot) (esm.py:340), the neutral-only correction, with no rho_n/rho_q split. The two expressions coincide only when q = rho_tot.sum()*dvol = 0. For a net-charged cell the autograd strain derivative of esm_energy_strained is therefore NOT the strain derivative of esm_energy, so the ESM stress is inconsistent with the ESM energy/force it is meant to differentiate.

# Final remediation — "Reconcile docstrings/unit comments with implementation"

Two independent fixes, one per file. Fix A is a real design change (collapses a doc/impl contradiction into an unrepresentable state); Fix B is label-only.

## Fix A — `src/gradwave/scf/guess.py`: a single per-atom weight contract

### The formalism (the object)
One per-atom weight vector `w ∈ ℝ^{na}` (float64, on `grid`'s device), resolved **once** before the species loop by a named, unit-testable helper that *is* the documented override contract:

```
w[a] = 1.0                              if species_scale is None and atom_scale is None
w[a] = species_scale[species_of_atom[a]]   if only species_scale given   (per-species broadcast)
w[a] = atom_scale[a]                        if atom_scale given           (OVERRIDE — replaces, never multiplies)
```

### FIX 1 — `_simpson_index_weights` via additive stencil accumulation

**File:** `/home/wladerer/github/gradwave/src/gradwave/pseudo/radial.py`, lines 38–59 (the whole body of `_simpson_index_weights`; the `else:` even-branch at 51–58 is where the confirmed ~11% over-integration at n=4 lives — `m = n-3 = 1` makes `w[m-1]` and `w[0]` the same element, and `w[0]=1/3` is then overwritten by `w[m-1]=1/3+3/8`, so the panels double-count and Σw = 10/3 instead of 3).

**Contract / formalism.** A composite Newton–Cotes rule is a *sum of local panel stencils*. Build the weight vector by `+=`-accumulating whole stencils over a tiling of the `n-1` intervals; shared boundary nodes then receive the sum of both neighbours' contributions automatically, and no seam can be double-counted because every interval is covered exactly once.

- Tiling rule: cover `[0 .. n-1]` with Simpson-1/3 panels (2 intervals each, weights `h/3·[1,4,1]`) as far as parity allows; close an even count with a single 3/8 panel (3 intervals, `3h/8·[1,3,3,1]`) over the last four nodes.
- Odd `n`: pure 1/3 tiling — reconstructs the current odd branch bit-for-bit.
- Even `n ≥ 6`: `(n-4)/2` 1/3 panels over `[0 .. n-4]` **plus** one 3/8 panel over `[n-4 .. n-1]`; the shared node `n-4` correctly accumulates `1/3 + 3/8`.
- Even `n = 4`: zero 1/3 panels, one 3/8 panel over `[0..3]` → `[3/8, 9/8, 9/8, 3/8]`, Σ = 3. Emitted with no special-case branch — it is just the degenerate tiling.

**Signature (unchanged):** `_simpson_index_weights(n: int) -> np.ndarray`
**Postcondition (strengthened, asserted):** for every `n ≥ 4`, `Σ w == n - 1` (exactness on the constant/linear; cubic-exactness follows from the stencils). Assert it before returning — this is the cheap self-certifying invariant that makes the class of bug unrepresentable.

**Reference implementation:**
```python
def _simpson_index_weights(n: int) -> np.ndarray:
    """Composite Newton–Cotes weights in the mesh index: ∫f dr = Σ f·rab·w.

    Assembled by accumulating local panel stencils over a tiling of the n-1
    intervals — 1/3 panels as far as parity allows, one 3/8 panel to close an
    even count. Shared nodes accumulate both panels' weights, so no seam is
    double-counted. Odd n reduces to the plain 1/3 rule; n=4 to the pure 3/8
    rule. Uniformly O(h⁴).
    """
    if n < 4:
        raise ValueError("need at least 4 mesh points")
    w = np.zeros(n)
    # number of leading intervals closed by 1/3 panels (even); rest by one 3/8
    n_third = (n - 1) if (n % 2 == 1) else (n - 4)
    for i in range(0, n_third, 2):          # 1/3 panels: nodes i, i+1, i+2
        w[i]     += 1.0 / 3.0
        w[i + 1] += 4.0 / 3.0
        w[i + 2] += 1.0 / 3.0
    if n % 2 == 0:                          # 3/8 panel over the final 4 nodes
        w[n - 4] += 3.0 / 8.0
        w[n - 3] += 9.0 / 8.0
        w[n - 2] += 9.0 / 8.0
        w[n - 1] += 3.0 / 8.0
    assert abs(w.sum() - (n - 1)) < 1e-12   # self-certifying: no seam double-count
    return w
```
This reaches both the numpy path and the torch delegators through the unchanged `simpson` at line 62 (`g.shape[-1]`), zero blast radius.

# Final remediation: one `Symmetrizer` contract, two conforming sites

## The object: a documented contract, not a base class

Add to `src/gradwave/.../symmetry.py` a single doc-authoritative `Symmetrizer` Protocol. It is typing + prose only (no runtime machinery), so existing free functions (`symmetrize_tensor`, `symmetrize_atom_tensor`, `symmetrize_forces`, `VectorFieldSymmetrizer`) satisfy it structurally without refactor.

```python
from typing import Protocol
import torch

class Symmetrizer(Protocol):
    """Graph-preserving idempotent linear projector onto an invariant subspace.

    Every symmetrization post-step MUST guarantee:
    (1) graph-preserving — no .detach(); out.requires_grad iff in.requires_grad.
    (2) idempotent projector — apply(apply(x)) == apply(x) to machine precision.
    (3) dtype/device transparent — exact in float64/complex128, CPU+CUDA;
        returns the input's dtype and device.
    (4) invariant-last — any HARD invariant (acoustic sum rule) is imposed by
        the FINAL projection, so it holds EXACTLY on the returned tensor.
        No averaging/transpose/re-symmetrization may run after it.
    """
    def apply(self, x: torch.Tensor) -> torch.Tensor: ...
```

The load-bearing graft from the runners-up is folded into guarantee (4)'s rationale: **a hard invariant must be imposed by an operator that commutes with every soft symmetrization already applied, so composition order cannot matter.** That reframes the phonons bug from "a step in the wrong order" to "a state the code cannot represent."

## FIX A — `symmetrize_forces`: restore the autograd edge

One-line deletion, no numerics change. Drop `f = forces.detach()` and accumulate from `forces` directly, matching the graph-preserving pattern already used by `symmetrize_tensor` (which uses `torch.einsum` straight off `z`, no detach). This is the only site among the tensor/atom-tensor/vector-field symmetrizers that violates guarantee (1); the docstring already claims consistency with them.

```python
def symmetrize_forces(forces, sg, cell):            # (na,3) -> (na,3)
    a_t = np.asarray(cell, dtype=float).T
    dev = forces.device
    acc = torch.zeros_like(forces)                  # inherits input's grad path
    for w_mat, amap in zip(sg.rotations, sg.atom_map, strict=True):
        s_t = torch.as_tensor((a_t @ w_mat @ np.linalg.inv(a_t)).T,
                              dtype=forces.dtype, device=dev)
        idx = torch.as_tensor(amap.copy(), device=dev)
        acc = acc + forces[idx] @ s_t.T             # was f = forces.detach()
    return acc / sg.n_ops
```

## FIX B — `gamma_hessian`: ASR as the terminal symmetric projector

The current tail (symmetrize → `hblk[a,:,a,:] -= hblk[a].sum(axis=1)` → re-symmetrize) makes the **transpose-average the last operation**, silently reintroducing ASR violation (nonzero Γ acoustic modes). Replace it with: symmetrize first, then apply the acoustic projector `P = I − TTᵀ` on both sides, where `T` (3na×3) spans the orthonormal rigid translations.

Because `P` is symmetric it **commutes with the Hermitian-symmetrization** `H ↦ (H+Hᵀ)/2`, so `P·H·P` is simultaneously symmetric AND satisfies `H·T = 0` exactly, and the two projections are order-independent (the runner-up's "order-independent orthogonal projection onto Hermitian ∩ ASR"). This is the whole defect closed as an unrepresentable state.

**Concrete, in numpy** — the winner's torch sketch must be transcribed to numpy, since `reconstruct` returns a numpy array and this function never touches autograd:

```python
def _acoustic_projector(na):
    T = np.zeros((3 * na, 3))
    for g in range(3):
        T[g::3, g] = 1.0
    T /= np.sqrt(na)                      # orthonormal rigid translations, TᵀT = I
    return np.eye(3 * na) - T @ T.T       # P = I − T Tᵀ, symmetric

# replace the h2-symmetrize / ASR-subtract / re-symmetrize block with:
h2 = 0.5 * (h2 + h2.T)                    # (a) symmetric FIRST
P  = _acoustic_projector(na)             # (b) hard invariant LAST
h2 = P @ h2 @ P                           # symmetric AND H·T = 0 exactly
return h2.reshape(na, 3, na, 3)
```

Note the projector is **unweighted** (identical masses in `T`). That is deliberate and correct: `gamma_hessian` returns the bare eV/Å² Hessian, and `gamma_frequencies` applies mass-weighting afterward as `H / sqrt(mᵢmⱼ)`. An unweighted `P` zeroing the rigid translations of `H` yields exactly-zero *mass-weighted* acoustic modes downstream, per the runner-up's mass-weighting check. (If a mass-weighted Hessian were ever projected in place, `T` would instead need columns `sqrt(mₐ)·ê_g`; not the case here.)

Verification target from the proposal: old path leaves `|H·T| ~ O(1)` residual; `P·H·P` gives `|H·T| ~ 3e-16`, asymmetry `~1e-15`, three smallest `|eigenvalues| ~ 3e-16`.
