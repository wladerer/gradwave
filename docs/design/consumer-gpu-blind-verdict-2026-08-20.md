## STRUCK (already tried and measured, or no regime exists)

**#7 Sketched orthonormalization for n_add > 16 — STRUCK: the regime does not exist here.** `_QR_CPU_MAX_COLS = 16` in `solvers/davidson.py:95` with the sweep comment: Davidson's `n_add ≤ nb` is "comfortably under 16 for the systems in this repo's benchmark battery", so the tall QR is already CPU-offloaded on every ordinary round (measured >10× on the 3050, performance.md). Blocks wider than 16 belong to LOBPCG/CheFSI, which are closed solvers (`static-subspace-solvers-already-lost`: 2–8× slower than Davidson). And the same GEMM-shaped-replacement class was already built and measured: CholQR2 (`_cholqr2`, `GRADWAVE_CHOLQR`) is neutral-to-negative on the 3050 (davidson.py:16–22, `benchmarks/ab_speedups.sh`), default off. Nothing left to win.

**#8 Constant-factor complex-GEMM sweep — STRUCK: each piece has a measured negative.** (a) Hermitian half-store / HERK-shaped S: Toeplitz extension #4 measured "GEMM speed NEUTRAL — torch has no faster complex-hermitian GEMM path; triu-build slower than full". (b) 3M/Karatsuba complex multiply requires a real-split rewrite; the real-split end-to-end was measured 0.92× (`whole-step-compile-complex-blocked`). (c) The S build already avoids conj materialization via lazy-conj views (davidson.py:512, the A100 memory-spike fix); einsum vs matmul measured identical (performance.md). (d) The one live-looking piece — fp32 s/x/hx GEMMs with fp64 upcast — was explicitly built and measured: 13–18× on the raw GEMM but a hard 1–2e-5 residual floor, never reaches 1e-9 (performance.md, "fp32-compute, fp64-accumulate for s/x/hx alone"). Its only legitimate reincarnation is inside #1's *emulated-fp64* machinery, which is precision-safe by construction.

**#6 Whole-solve CPU placement at small sizes — STRUCK as a perf lever.** Three measured results close it: (i) performance.md "What does not help": "A structural GPU rewrite for small systems. The small-system GPU gap is fp64 precision, not launch latency or eager-mode overhead." (ii) The streaming/residency redesign was given a specific accounting that "comes out roughly flat" (subspace build CPU-favored 198 vs 329 ms, but Ritz combine GPU-favored 164 vs 215 ms, h_apply needs v on GPU). (iii) The device crossover is *batch width*, not atom count — on many-k NC the 3050 beats the 22-core CPU 2.6–5.6× even on 1–2-atom cells (performance.md, delta_gauge campaign), so "small instance ⇒ CPU" is wrong for exactly the batched pipeline this spec describes. The wins that exist at small shapes were already taken piecemeal with measured gates (`_eigh_subspace` ≤ 256, `_qr_offload` ≤ 16 cols). Residue worth maybe an issue, not a build: a per-signature whole-*run* device advisor (UX, not a kernel attack).

**#3b Rank-truncated incremental density rebuild — STRUCK (park with a cheap kill-signal probe).** The premise (Δρ between outer iterations is low-rank in the joint span) was already tested from the other side: Toeplitz extension #7 measured that inter-iteration δV/δρ structure is "concentrated but NOT bandlimited" (47% of power at |G|<0.2Gmax but ~30% in the tail) — the same slow decay predicts the aligned 2B×2B Δ-core won't truncate hard until the run is nearly converged, exactly when few iterations remain. Combined with high effort (gauge alignment + error ledger + a second density path to keep exact) and `density_b`'s slice being only part of the field work, EV is negative. If ever revisited: first measure the eigenmass profile of the aligned Δ core on a real run (one afternoon, no build) — that is the kill signal.

## SURVIVORS (ranked)

### 1. Ozaki-scheme emulated-fp64 GEMM for the dense local apply (attack #1) — the invited open avenue

**Code sites.** `core/batch.py`: `_local_toep` (line 345, the exact `M @ c` GEMM), `_toeplitz_M` (331) + `_toeplitz_idx` (314) for the M build, `_use_toeplitz` (378) — the per-signature measured-verdict gate that this path plugs straight into, `_TOEPLITZ_ON_CUDA` (81) currently False, `_TOEP_VERDICT` key (83). Certification reuses the machinery PR #329 just landed: `_certify_fp64` in `solvers/davidson.py` (commit `5ff217e`) — no band declared converged by a low-precision measurement.

**Why it survives vetting.** The CUDA Toeplitz variant is the explicitly open avenue: fp32 M@c measured 2.75×/6.53×/2.52× at npw 259/1917/6375 on the 3050 at apply level, but whole-SCF fp32 was negative for two reasons — fp32 draft noise costs outer iterations on metals, and the fp64 polish/non-apply work is crippled (toeplitz memory note, "GPU WHOLE-SCF is NEGATIVE"). Ozaki splitting attacks reason 1 head-on: mantissa-sliced fp32 GEMMs recombined in fp64 give ~fp64-accurate products from the fast units, so there is no draft noise to perturb the SCF path and no polish phase to cripple — it also removes #329's certification-collapse fallback (the fp64-expansion finish) since applies are near-fp64 everywhere. It is the one precision scheme *not* covered by the documented fp32-RR failure (performance.md) because the delivered accuracy is ~2⁻⁴⁸–2⁻¹⁰⁴, not 2⁻²⁴.

**Sketch.** (i) `_local_toep_emulated(c)`: split Re/Im of M and c into 2–3 fp32 slices (row/column power-of-2 equilibration first — v̂ spans decades), run the slice-pair GEMMs via cuBLAS SGEMM (true fp32, TF32 off: `torch.backends.cuda.matmul.allow_tf32 = False` around the call), fp64 recombination. Slice width must respect the K≈npw accumulation bound (11-bit slices are exact only to K≈4k with fp32 accumulate; pick width from npw, or accept the bounded error and certify). (ii) Add the path as a third contestant in `_use_toeplitz`'s timed trial (key already includes device/dtype; add a path tag), CUDA-only, budget-checked against `_TOEPLITZ_M_BUDGET_BYTES` (slices ≈ 1.5× M's fp64 bytes; 6 GB card — keep the 256 MiB default). (iii) Wire the residual certification: run the solve with emulated applies, certify with `_certify_fp64` exactly as #329 does (one exact nb×nb RR against the FFT-path fp64 apply). (iv) Phase 2, only if phase 1 wins: apply the same emulated GEMM to the RR subspace build/Ritz combine (davidson.py:512, 517–518) where fp64 is roofline-bound at ~123 GFLOP/s and the raw fp32 gap is a measured 13–18×.

**Effort.** ~3–5 days including the asus A/B (`scripts/gwq --host asus bench ...`).
**Expected gain.** Apply-level ~1.5–3× on the 3050 (roughly half the pure-fp32 numbers, at fp64 accuracy); whole-SCF ~1.2–1.4× where the apply is 25–37% of wall, stacking with (partially overlapping) #329's 1.16×. Dies at large npw with the same M-budget gate as CPU Toeplitz.
**Gates.** `tests/unit/test_toeplitz_local.py` (exactness vs FFT path becomes a *tolerance* assertion for this path — assert ≤ certified bound, keep the 1e-16 assertion on the exact paths), `tests/unit/test_davidson_fp32_expansion.py` (certification contract), `benchmarks/ab_speedups.sh` — its stated kill signal is exactly right: outer-iteration parity on al/cu, +1 iteration means the path is perturbing the SCF; `bench_matrix` battery for wall.

### 2. Outer-residual-slaved precision for the non-eigensolver field FFTs (attack #3a)

**Code sites.** `scf/loop.py`: `effective_potentials` (547) → `hartree_potential_r` (core/energies/hartree, already rfft) + XC on the dense grid; `_output_density` (1294) → `density_b` (core/batch.py:475); the mixer packing `_mix_densities` region (1211); the existing tolerance ladder `adaptive_diago_tol` call (~1666) supplies the outer-residual signal (`history`), and the fp64 renormalization precedent at loop.py:959 shows how charge conservation is protected (performance.md notes the density build "stays fp64 for charge conservation" — the G=0 renorm trick is the answer).

**Why it survives.** Untried as such: everything measured so far put fp32 in the *eigensolver* (whole-solve draft `davidson_batched_ms`; per-apply #329). The field FFTs were never precision-scheduled, and the 3050 evidence says they are now the binding slice ("the bottleneck has MOVED to the non-apply FFTs — density build, Hartree, XC", toeplitz note; density_b sets the mixed-precision floor per performance.md). The known hazard is sharply documented — the fp32 draft added +2 outer iterations on Fe/Cr, device-independent — so the kill signal is free: iteration parity on the metal battery. The design must respect the inexact-secant safe zone (cap injected field error at ~0.1× the current density residual; the mixer history is the fragile part), and the final accepted iteration always reruns fully fp64 (certification by construction, same logic as the draft/polish split).

**Sketch.** Thread a `field_dtype` through `effective_potentials`/`density_b` chosen per iteration from `history` (fp32 while ‖Δρ‖ ≫ ~1e-5·√N, fp64 after, fp64 always on the convergence-check iteration); drop mixer history pairs straddling the switch (one flag in the `PulayMixer/JohnsonMixer` step); renormalize ρ's electron count in fp64.
**Effort.** ~2–4 days.
**Expected gain.** On the 3050, the eigensolver-only fp32 draft already measures 1.18–1.39× on insulators; this targets the complementary slice, ~1.15–1.3× if metal iteration parity holds — that is the coin-flip (p ≈ 0.4–0.5; the fp32-draft precedent regressed every metal via exactly this class of noise, though through a different injection point with no budget cap).
**Gates.** `ab_speedups.sh` iteration-parity kill signal; `bench_matrix` seven-system battery (metals are the verdict); QE fixture reference comparisons (`tests/fixtures/qe`) and the PW metamorphic suite for final-answer exactness.

### 3. Batch compaction / per-k retirement in the lockstep solver (attack #5)

**Code sites.** `solvers/davidson.py` lines 525–561: `n_add = int((rn > tol).sum(dim=1).max())` — the max is over *all* k, so one straggler k sets the width and the fully-converged ks keep riding through every GEMM/FFT; the expansion, `_orthonormalize_b`, `h_apply` (through `BatchedHamiltonian.apply`, keyed to `bk.mask`/`flat_idx`/`p` — a compacted sub-batch needs an indexed view of the per-k tables; PR #328's fix is the precedent that reindexed `BatchedK` views must not alias parent caches).

**Why it survives.** Genuinely untried: `sync_free` and CUDA-graphs attacked launch overhead (both null); nothing ever shrank the k-batch mid-solve. Zero numerical risk (retired ks keep their certified eigenpairs; remaining ks see identical math). The per-band `n_add` shrink already exists, but the nk axis — which multiplies every FFT, QR, eigh, and the RR build — does not shrink today. Convergence skew across k is real in the warm regime (most ks 2–3 rounds, stragglers set the count).

**Sketch.** When `(rn > tol)` rows go all-False for a k, gather `v/hv/x/t/mask/flat_idx/p` (and the Toeplitz M/idx if active) into a K′ sub-batch at power-of-two-ish shrink thresholds; scatter results back on exit. Keep it inside `davidson_batched` behind a flag; the per-k H tables are views, so the one-time gather per shrink is a few MB.
**Effort.** ~2–3 days (the fiddly part is the compacted `BatchedHamiltonian` view).
**Expected gain.** 1.05–1.2×, best on warm many-k metals (the regime that fills the 3050 per the batch-width finding); latency-floor-capped at tiny K.
**Gates.** Bit-exact per-k eigenpairs vs uncompacted (an algebraic identity — assert it), existing davidson unit tests + null tests, iteration parity for free.

### 4. Gauge-aligned Ritz-block extrapolation across outer iterations (attack #4)

**Code sites.** `scf/loop.py` `_seed_orbitals` (~700) seeds iteration 1; thereafter `coeffs_b_s[sp]` carries last iteration's X into `_solve_bands` (1690s) raw — no alignment, no extrapolation. Add at the end of the iteration body: per-k B×B overlap `X_{t−1}ᴴX_t`, polar factor (CPU-offloadable like `_eigh_subspace`), `X_pred = X_t + θ(X_t − X_{t−1})`, re-orthonormalize via `_orthonormalize_b`.

**Why it survives (with damped expectations).** Untried, near-zero cost, self-repairing (a bad extrapolation costs nothing — the first RR fixes it). But the codebase's own measurements cap the ceiling: warm SCF steps already run 2–5 Davidson rounds (`small-cell-scf-latency-bound`), the LCAO-seed investigation concluded warm-start quality has a low ceiling because Davidson already warm-starts across steps, and the tol-ladder experiment measured step-2 inner iterations *identical* regardless of step-1 seed quality. Expect 0–1 rounds saved per solve.
**Effort.** ~1 day. **Expected gain.** 1.0–1.1×; worth doing only because effort is trivial and it is the prerequisite alignment machinery if #2 is ever built.
**Gates.** Iteration parity + converged-energy identity (bench_matrix), metamorphic suite.

### 5. Cross-iteration subspace recycling with exact incremental HV (attack #2)

**Code sites.** `solvers/davidson.py` `davidson_batched` (accept optional `(v0, hv0)`), `scf/loop.py` `_solve_bands` (~954, would return/accept the final basis), the Δ-apply is a `BatchedHamiltonian` built with `v_eff = Δv` — exact for the *plain* NC path because between iterations H changes only through v_eff (kinetic `bk.t`, projectors `p`, `dij_full` all static at fixed ions). **Must be gated off** when the operator drifts elsewhere: Fock rebuild (`fock.rebuild`), meta-GGA `metagga_apply_s`, Hubbard `hub_dij`/U-ramp (`u_scale`), all in the loop body — each changes H outside the local term and breaks the incremental identity.

**Why it survives (last).** Untried — today only X (nb vectors) is recycled, never the 4nb basis, and HV is always recomputed from scratch. The exact update HV += ΔV·V is mathematically clean and is *not* the parked Toeplitz-ext-#7 idea (that truncated ΔM; this applies the full ΔV, exact). But three measured facts discount the EV: warm solves are already 2–5 rounds (the glue it attacks is already small per solve); the recycled-basis conditioning issue is real (the restart-drift fix at davidson.py:577–591 exists precisely because Ritz blocks accumulate orthonormality drift); and the fp32-Δ-apply refinement, while a legitimate #329 extension, adds a ledger whose failure mode is the same metal-iteration inflation as every prior precision experiment. Storage: 4× the Ritz block on a 6 GB card — fine at small/medium, check against `_GPU_DENSE_BUDGET_BYTES` thinking.
**Effort.** ~1–2 weeks (solver signature, SCF threading, drift re-orthonormalization, the gating matrix). **Expected gain.** Discounted to 1.05–1.2× (from the claimed 1.2–1.5×), plain-NC only.
**Gates.** Converged-energy bit-identity + iteration parity (`ab_speedups.sh`), davidson unit tests, metamorphic suite; a dedicated null: recycled-basis solve must match cold-basis eigenpairs to tol on a fixed H.
